# Evaluation-only optimized mappings and a completing CDCL baseline

Do not relabel the prior identity-alignment pilot as an oracle upper bound.
This experiment searches permutations at evaluation time. It is a best-found
oracle, not a certificate of optimal mapping or minimum repair cost unless an
explicit bound is met. A failure cannot eliminate unsearched mappings.

## Backend prerequisite

Use native Glucose 3.0 from the official python-sat 1.9.dev15 source archive,
whose PyPI sdist SHA256 is
5a2a58022248ce2cf9395b560685185e4773c452a29eb0ae8662d67611336cd3.
Keep all search heuristics, minimization and restarts at their original defaults.
Syntax-only Clang fixes and three observational counters are recorded by the
builder. Build a counter-disabled control; compare status, conflicts,
decisions, propagations and the complete DRUP byte hash. This tests whether
instrumentation altered the search, not statistical solver performance.

Counters are deliberately separate:
- analysis_resolution_steps: first-UIP reason antecedents after the initial conflict;
- minimization_reason_visits: attempted reason visits during learned-clause minimization;
- binary_minimization_candidates: inspected binary candidates in minimization;
- conflicts, decisions and propagations, plus actual solve time.

These are actual native CDCL operations, not the old enumerator's candidate
attempts and not the number of steps generated by proof conversion. Do not
silently add incompatible counters or report them as universal proof-search
complexity. Report reductions component by component. Both routes use the same
native binary, 1,000,000 conflict cap and 30-second process limit.

## Oracle objective and scope (fixed before oracle outcomes)

Initially use the existing checked historical Resolution DAGs for the 120- and
200-vertex pairs; keep the 120 pair explicitly as a milliseconds-scale control.
Do not regenerate H/T or change their topology. Native BLIND must finish first.
The 320 pair is a backend/proof-transport check until an appropriate complete
Resolution artifact is available. Native drat-trim has verified its saved
DRUP and emitted LRAT in ~7.1 seconds, but LRAT verification is not a direct
PASS by the project's existing Resolution checker.

Evaluation optimizer: 90 seconds per pair, fixed RNG 730001, multistart
annealing of vertex permutations, retaining 12 best distinct candidates.
Score is the number of historical inferences whose complete original
ancestors replay under that permutation; matched leaves break ties. Source
proof parents are fixed. Within-vertex clauses always match; cross-vertex
exclusions match exactly when the mapped edge occurs in T. Global color
permutation does not change that score because T is color-symmetric.
Identity is evaluated explicitly as an arbitrary control, never called oracle.
For actual solving, try all six global color permutations of each retained
mapping. Pick the lowest observed analysis_resolution_steps among completed
and eventually checked routes; report every candidate, the best-found status
and the trivial score upper bound. Selection is privileged evaluation, not
held-out prediction or an automatic mapper.

## What is measured

BLIND runs on T. History replays valid old inferences, checks the resulting
Resolution module, then the same native solver completes T with those checked
lemmas appended after the identical original clause prefix. Final DRUP is
converted to pure Resolution, composed with replay, and checked against T.
The remainder is whole-goal CDCL completion, not an optimal local-gap repair
algorithm. Report that boundary explicitly; this tests whether direct historical
work can help a real completing search. It cannot disprove the value of other
repair strategies. Missing premises never become input axioms.

If no nontrivial checked lemma replays, the augmented CNF is exactly T and no
completion run should be miscounted as a history benefit. Historical extraction,
oracle search, replay checking, completion search and certificate conversion
are separate costs; oracle search is free only in the hypothetical mapping
experiment. No claims about automatic retrieval/mapping follow.
