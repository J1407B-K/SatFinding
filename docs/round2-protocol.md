# 第二轮实验协议

## 独立重命名

数据仍为 SATLIB 官方 500 对 RTI/BMS；本轮对每个公式独立进行随机变量置换，属于
原始基准的受控变换，不再称为“未改写的原始文件”。每个公式的变量编号池为 1..v，
不使用按实例划分的编号区间；此轮不翻转文字极性。历史和查询顺序还分别打乱，防止
用数组位置恢复父子关系。随机种子 7101/7102/7103。隐藏对应关系仅留在评估驱动和
单独 private JSON，`structural.py` 仅接收 CNF/证书，不接收配对 ID、名字或真实映射。

三次置换不是三个独立数据集。WL 具有重命名不变性，重复种子用于检验稳健性，不能
把 500 个原始配对当作 1500 个独立样本计算显著性。

每次置换都用真实对应关系在评估端检查历史模型可迁移；这只是可行性上界，不计为
系统检索/匹配成功。整公式 exact/canonical、原始子句 Jaccard、64 路 MinHash、
TF-IDF、BM25-like、随机排序，以及 0..2 轮 WL 图特征均处理同一历史库。
TF-IDF/IDF/BM25 参数只用历史文档统计，不使用查询或父实例标签。

初始阶段：所有 500 个查询计算 Recall@1/3/8/32 和 MRR；第一个置换种子取打乱后
前 20 个查询做端到端 pilot。发现样本过小后，固定扩大到前 100 个，包含原来的 20 个，
未按是否命中挑选。每种排序最多送入 3 个候选；每次原生 LAD 搜索预算 0.25 秒。
额外 oracle-candidate 对照只提供正确历史索引，仍由 matcher 自行求映射。

## 结构匹配与检查

图包含正/负文字节点、互补文字配对边以及带宽度类型的子句节点。候选变量映射保持
极性；使用非诱导图匹配，但子句宽度相同，因此映射后仍要显式检查子句精确包含关系。
SAT 方向匹配 query 到 history，然后把历史模型投影到查询变量；UNSAT 方向匹配历史
证书前提到 query，再迁移整个 resolution 证明。最终均调用原来的 `check`。

igraph 1.0 的运行接口不接受文档中残留的 time_limit 参数。本项目用 Linux fork
子进程隔离原生搜索，并在预算耗尽后终止该子进程。图构建/候选域构建和清理开销另计，
所以整个调用可能长于 0.25 秒。超时/失败不构成 SAT 或 UNSAT 结论。

## Scorer 与表示的解耦

原始子句 token 在独立重命名后失效，是表示层面的干预，不足以说明某个 scorer 优越。
因此额外把相同 WL token 分别交给 Jaccard、MinHash、TF-IDF 和 BM25，测量同一表示
下的排序差异。WL 使用确定性图细化特征，没有神经模型或训练。

## 非父子 motif

生成 24 个经求解器检查并最小化的二元 UNSAT core，至少有 6 个变量；去除整 core
在 signed canonical 意义下的重复。用参考求解器生成 resolution 证书并验证。
这是一组人工构造的结构工作负载，不冒充工业或官方 SATLIB 数据。

每个历史 H 与查询 R 包含同一个隐藏 core，但有独立生成的可满足随机噪声，随后
分别独立重命名。检查它们在原始命名空间中双向都不是子句子集，且全局子句数不同。
上下文从包括 motif 变量的变量池采样，允许上下文与 motif 相连。

- control：H/R 分别加 80/110 个三元噪声子句。
- mixed：另外各加 12 个二元噪声子句，干扰基于宽度的 motif 提取。
- 每层另有 12 个已检查 SAT 模型的负例，不能接受任何 UNSAT 迁移。

普通检索查看整个 H/R。`proof_wl` 把历史证书前提作为索引文档，把 query 的全部
二元子句作为查询视图；这里没有拿到隐藏的 query core。`proof_canonical` 对同一
局部视图做精确规范化，作为“局部 canonical 已足够”的重要对照。控制层可能主要
衡量宽度投影的收益，不能据此声称能发现任意混合子句中的隐蔽 motif。

检索到原植入来源和实际合法复用分开报告：别的历史证书若也能迁移并通过检查，同样
是合法命中。负例上任何接受都会令实验失败。真实源 ID 仅用于事后 rank 评估。

## 不支持的推断

本轮不以净加速为成功前提；结构匹配可能比直接求解贵得多。需要分别报告排名、映射、
验证和成本，不能用 oracle 映射或已知 core 的存在代替系统成功，也不能把人工 motif
实验的成功当作神经 embedding、通用子图检索或生产 UNSAT 工作负载的结果。

算法来源：[WL graph kernels 原论文](https://jmlr.org/papers/v12/shervashidze11a.html)、
[igraph 图匹配接口](https://python.igraph.org/en/main/api/igraph.GraphBase.html)。
