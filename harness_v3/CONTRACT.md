# V3-capable harness contract

Capacity revision only. Identity v2 byte semantics, native early-enqueue/reason legality, proof semantics, and temporal v1.1 schema/formulas are retained. The two canonical identity functions are copied byte-for-byte from qualified harness_v2; heap and bounded queue semantic exporters are unchanged. Old harness code, binaries, packages and locks remain immutable.

Collection accepts a SHA-256-frozen JSON plan with collections. Each collection supplies target, original input path/hash, requested_state_count, K (1..6), and checkpoint_rule: kind=first_eligible_per_window, ordered disjoint inclusive conflict windows, minimum_legal_count. The wrapper validates the plan and records its exact numeric native compilation. There is no native target, checkpoint-window or state-count constant. One native baseline process per collection exports at most one state per window, continues to subsequent windows, and stops when the request is satisfied or windows end. Shortfalls are retained and rejected by cohort freeze, never silently replaced. Selection depends only on the frozen plan and current legal-action set. Package artifacts are exported to unique directories, assembled and hashed before ground truth; no action outcomes are available during collection.

K is read from the plan and bound inside every package. All eligible clause creation IDs are sorted; full actions for exactly first min(K,legal_count) are frozen. The pre-GT auditor independently recovers assignments and clause content from canonical preimages, checks the entire eligible ID set, first-K ordering, action content, implied literal, source and legality. Replay never enumerates candidates or falls back.

Canonical logical and heuristic text/hash verification remains mandatory, along with exact observer boundary ordinal and native counters. Every package additionally binds prefix analysis-resolution steps, redundancy, binary, watcher, dequeue and enqueue counters. State JSON includes propagations/enqueues parsed from its canonical logical preimage. The replay checkpoint independently emits these counters and the runner verifies equality before accepting the route. Native final results include analysis-resolution steps, conflicts, decisions, propagations, enqueues, dequeues, watcher, redundancy and binary counters. Proof path and SHA-256 are attached by the proof-verifying runner. All inputs are original frozen CNFs. This qualification exercises UNSAT with independently checked DRUP proofs; SAT result plumbing does not replace proof/model validation requirements.

The immutable cohort manifest binds packages, plan and build hashes. Dynamic expected routes are one baseline plus each frozen action per package. Route IDs remain SHA256(package_manifest_sha256 + ':BASELINE') or SHA256(package_manifest_sha256 + ':ACTION:' + rank + ':' + stable_id). Cohort/package artifact sets, IDs, canonical hashes, temporal reference checks, route counts, proof checks and no-emission checks are generic and shared between qualification and future science. Pre-GT freezing makes scientific input files read-only. Post-route audit rechecks full input hashes, exact requests, output file allowlist, native results, proof evidence, source and binary hashes.

Finalizer is gated by a fresh generic route audit. Remaining ops are final analysis_resolution_steps minus frozen prefix_analysis_ops; delta is 100*(action_remaining/baseline_remaining-1), HIGH iff abs(delta)>=10. Zero baseline remaining ops is an explicit non-computable error, never substituted with another metric. State format is SENSITIVE if any tested action is HIGH, otherwise INERT within frozen tested-action budget. Qualification uses the same finalizer only as an infrastructure dry run; its labels provide no temporal science evidence.

The collector and replay binaries are separately compiled. Replay cannot compile the collector's candidate scan, plan iteration or action/raw export. File hashes, command validation and output allowlists are required; neither emissions nor route success are inferred merely from a constant metadata flag. Qualification-specific coverage requirements (multiple states per target and an actual rank 6 route) belong only to the qualification orchestrator, not to the generic auditor/finalizer.
